## 1. Uncertainty Quantification Architecture

In accordance with PRD §4.3 and Rule 5, deterministic countdowns and point-estimates are scientifically prohibited. The repository implements uncertainty modeling via **Quantile Regression**:

- **Lower Bound ($P_{10}$)**: Represents favorable recharge conditions (10th percentile depth, shallowest water table).
- **Median ($P_{50}$)**: Expected standard depth.
- **Upper Bound ($P_{90}$)**: Severe deficit / high drawdown stress scenario (90th percentile depth, deepest water table).

## 3. Calibration Gaps & Deficiencies

1. **Quantile Crossing Phenomenon**:
   Fitting independent `GradientBoostingRegressor` models with `loss="quantile"` for each alpha does not guarantee mathematical monotonicity. In Baldeogarh, the 10th percentile predicted depth is 2.86m while the 50th percentile is 2.16m. This must be corrected using monotonic sorting (`np.sort([p10, p50, p90])`) or conformal prediction interval estimators.
2. **Empirical Coverage Verification**:
   The code does not currently compute empirical coverage rates (e.g. verifying that exactly 80% of true test observations fall between $P_{10}$ and $P_{90}$).
3. **Frontend Uncertainty Disconnect**:
   While the ML pipeline models real uncertainty, the frontend API route `/api/forecast` serves hardcoded static margins (`currentDepth - 0.20` and `currentDepth + 1.10`), masking the real empirical uncertainty.
